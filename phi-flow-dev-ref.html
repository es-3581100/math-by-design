Page-layer stack + prompt-to-box transition


This example separates visual depth from reading order. The background and logo establish identity; static boxes establish stable destinations; interactive text adds affordances; the prompt temporarily floats above them. The prompt should then hand the user back to an existing box instead of becoming a second navigation system.

Start with the permanent boxes visible. Open the prompt only when the user asks for a choice.

  






  
1 / TriggerUser clicks a clearly named button near the content that created the question.

  
2 / PromptOverlay asks one bounded question. Do not duplicate the whole page inside it.

  
3 / RelationEach prompt button maps to one stable box by target ID or semantic key.

  
4 / ReturnClose prompt, move focus to the target box, then briefly highlight it.






  
Best when the prompt is explanatory
Anchor it visually near the trigger on wide screens. On narrow screens, use a bottom-sheet style location so it does not cover the target hierarchy. Keep the underlying boxes visible when possible.

  
Best when the target is boxed text
Make the box the final state. The prompt button should say what the target contains—“Show evidence” beats “Continue”—and the transition should end with focus on that box.

  
Avoid
Prompt → second prompt → card → drawer chains. They break the relationship with the original boxed text and make keyboard/Back behavior harder to predict.

  
Phi Flow relation
The prompt may clarify a handoff, but it should not rewrite the semantic order. A 3 → 2 transition still ends at the decision content; the overlay is only a transient interaction layer.

Color on the Fibonacci scale


Use two related color systems for two different jobs. Direct convergence colors come from the HEX lab: every 90° turn samples a new hue while radius/saturation changes by φ. Those samples are useful for visualization, generated art, charts, and exported color cards. Interface colors should be calmer: keep one seed hue as the semantic accent, then increase its presence as the layout mass gets smaller. That preserves the 8 → 5 → 3 → 2 → 1 → 1 hierarchy without turning the interface into six competing accents.


Companions: Open the full HEX convergence lab for freeform sampling · Open the UI master color contract for the compact design-system rule.




  

    
Seed + mapping

    
The lab samples rotate 90° per node. The UI scale below instead locks the seed hue and uses Fibonacci-like tint strength: 8%, 13%, 21%, 34%, 55%, 89%.

    
#FF5A36single semantic accent seed

    

    

    

    
Semantic scale ready. Apply it to the layer demo above to see trigger → prompt → target color continuity.

  


  

    
Direct convergence samples

    
These six chips follow the lab model: hue advances one quarter-turn and saturation contracts by 1/φ on each inward node. Treat them as sample data, not six independent UI accents.

    


    
UI-safe role mapping

    
The larger the visual mass, the quieter the color. Small interaction states are allowed to carry more of the seed accent because they occupy less area and need stronger recognition.

    

  






  Prompt-to-box color relation
  
Color should help the transition feel continuous without making the popup itself the destination.

  

    
Trigger / tile 234% seed presence. Enough to announce an action without dominating the page.

    
Prompt / neutral surfaceKeep the temporary panel neutral. Use the 55% interaction token on choices/focus.

    
Target / tile 189% seed presence on the border/ring. The strongest color appears only after the destination is known.

  






  
Large surfaces: subtract color
Background and persistent boxes should use the 8–13% tokens. They carry identity through undertone, not through saturation.

  
Interaction: add color by state
Proof/route cues can use 21%; the decision uses 34%; focus/interactive feedback can use 55%. Do not promote all text to accent color.

  
Arrival: strongest, shortest
Use the 89% token for a temporary target ring or confirmation edge, then let it settle. Strong color marks the handoff, not permanent decoration.

Each agent owns an output and must hand over a verifiable artifact instead of silently changing a previous agent's design decision.

Failure example: proof arrives after the CTA


A builder moves the decision button inside the context block and before the proof strip. Visually attractive does not equal correct. The reviewer flags the 3 → 2 order inversion, cites the DOM positions, and sends a narrowly scoped patch request. The builder reorders the semantic elements (or requests an explicit contract scope change); the reviewer runs F3 again. The current template is documented as having this same class of drift in Known drift.

Dev layer


Open: φ DEV button, Alt/Option+G (matched on event.code, so it works on Mac), ?dev=1 for the scaffold, ?dev=live for Live view.


Scaffold view: the 13×8 contract on its own. Nodes drag or take arrow keys (Shift = 5%) and snap to tile edges within 10px. Positions persist under phi-flow-node-positions-v1; double-click a node to reset it.


Live view: the contract scaled over the real hero, plus an outline on every [data-tile] element. The panel lists one line per element: ok or !!, tile, size, font size, and whether its center sits in its own region. The last line checks DOM order against flow order. Clear every !! or decide to change the contract.



Known drift in the current template


Findings from reading the markup. Confirm each in Live view.


1. DOM order. The CTA (tile 2) sits inside the context column (tile 5), so it precedes the proof strip (tile 3). Move it after the proof strip or re-role it.


2. Tiles 3, 2, 1 in the hero. The contract places them bottom-right under tile 5. The hero puts the proof strip bottom-left across the full width. Either move the proof strip, or add a scope field to the contract (hero realizes 8 and 5; a later band realizes 3, 2, 1).


3. Flow demo spans. 7, 4 and 6 are not Fibonacci, and h2 and lede overlap at column 9. See the table in #compose.



Don'ts


The only detailed prohibition list. Machine copy: typography.forbidden in the contract; keep the two in sync.

Validation gate


5 / 5 required before adding visual ideas. Adapted from the validation gate in ui-build-ref-master.


#CheckQuestion


F1IdentityCan someone describe the page's idea without saying "modern", "clean" or "golden"?


F2MassIs there one primary claim with clearly more authority than its support?


F3FlowDoes Live view show no !!, with DOM order equal to flow order?


F4VariationDoes each handoff change two or more properties, with one accent carrying one meaning?


F5ResilienceDoes it collapse cleanly under 760px, with focus and reduced-motion states working?
